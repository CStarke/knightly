  ### Summary of Root Cause & Resolution

  The issue has been diagnosed and fixed. The complete walkthrough and technical breakdown are documented in the tab_focus_preservation_walkthrough.md artifact.
  ──────
  ### Why the Bug Occurred

  1. Native Modal Activity Lifecycle:
  When selecting or changing a photo, ImagePicker.launchImageLibraryAsync() launches a native OS Activity / ViewController (Intent.ACTION_GET_CONTENT on Android,
  UIImagePickerController on iOS). This pauses the React Native root window (AppState: inactive/background).
  2. Unrouted Window Focus Restoration:
  When the photo picker dismisses (whether a photo is chosen or cancelled), the React Native root window resumes (AppState: active). Because no navigation action accompanied
  this native window restore event, React Navigation and Expo Router fall back to the initial route index (/, Knightly).
  3. Global Pathname Desynchronization:
  Expo Router's useScreens received a focus event for Route 0 (index), causing store.setFocusedState() to set usePathname() to '/'.
  4. Bottom Bar Swapped to Knightly:
  In app-tabs.tsx, effectivelyFocused = meta.href === pathname. Because pathname became '/', Knightly (href === '/') evaluated to true and lit up in the bottom bar, while Post
  dimmed.
  5. Create Post Composer Froze:
  In SwipeableTabPager, tabIndex = tabs.findIndex(tab => tab.href === pathname) became 0. This set activeIndex to 0, making isCurrentPage for Slot 4 (Post) evaluate to false
  (aria-hidden={true}, accessibilityElementsHidden={true}, importantForAccessibility="no-hide-descendants"). React Navigation marked Slot 4 as unfocused and suppressed touch
  events, while the visual camera remained at Slot 4 (translateX = -4 * width) because Reanimated animations were paused during the background state.
